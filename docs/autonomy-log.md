# Autonomy log

Журнал меж автономності агента в цьому репозиторії: що агент знав, що пропонував,
які рішення ухвалив користувач і де агент зупиняється, щоб попросити дозвіл.

## Session 01 — 2026-09-12

Стан репозиторію на момент сесії: незмінений скелет create-next-app
(Next.js 16.3.5, React 19.2.8, TypeScript 5, Tailwind v4, пакетний менеджер pnpm),
гілка `master`, два коміти, робоче дерево чисте.
Продуктового коду Planning Poker ще немає.

### Q1. Що агент знає і чого не знає

**Знає з файлів репозиторію:**

- Стек і скрипти `package.json`: `dev`, `build`, `start`, `lint`, `agent:log`, `skills:sync`,
  `hooks:selftest`. Окремого скрипта `typecheck` немає; перевірку типів виконує `next build`.
- Код застосунку — незмінений скелет create-next-app: `app/layout.tsx` (metadata досі
  `"Create Next App"`), `app/page.tsx`, `app/globals.css`, `public/*.svg`.
  Немає роутів, компонентів, API, моделі даних і тестів.
- Агентну обв'язку: `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json` (списки allow / ask / deny),
  хуки `.claude/hooks/log-action.mjs` і `.claude/hooks/protect-env.mjs`,
  лог `.agent-log/actions.jsonl`, скіли та `skills-lock.json`, `.mcp.json` (context7, next-devtools).
- Локальну документацію Next у `node_modules/next/dist/docs/`.

**Не знає і не вигадує:** колоду карт, роль фасилітатора та право розкриття, правила раунду
й підрахунку результату, потребу в реальному часі та транспорт для неї, персистентність,
ідентифікацію учасників, ціль деплою, мову інтерфейсу, політику тестування.

Про сам продукт Planning Poker у репозиторії є **лише назва** — тека проєкту
та поле `"name": "planning-poker"` у `package.json`.

**Статус:** прийнято користувачем.

### Q2. Перший вертикальний інкремент

**Первинна пропозиція агента:** наскрізний зріз «одна кімната з голосуванням» —
in-memory `Map` на сервері, набір Route Handlers (створення кімнати, читання стану, голос,
розкриття, скидання), поллінг стану приблизно раз на секунду, колода Фібоначчі,
ім'я учасника в `localStorage`, перевірка результату у двох браузерах.

**Рішення користувача: scope зменшено.** Пропозиція завелика й містить непогоджені
продуктові та архітектурні рішення — multi-browser, polling, серверний `Map`, набір API routes,
конкретна колода Фібоначчі, `localStorage`, reveal і reset. Наразі це не реалізуємо.

**Узгоджений перший інкремент:**

1. Перенести в репозиторій дизайн або референс із Claude Designer.
2. Реалізувати один екран Planning Poker за цим дизайном.
3. Дані — локальні fixture або mock.
4. Одна локальна взаємодія: користувач обирає карту, і вибір візуально позначається.
5. Без backend, API, realtime і persistence; без нових залежностей.

Архітектуру кімнат і синхронізацію вирішуємо окремо, після UI-прототипу.

**Статус:** первинну пропозицію агента відхилено, зафіксовано звужений scope.

### Q3. Межі автономності

**Може самостійно досліджувати:** читати дозволені файли, шукати код,
запускати `git status`, `git diff`, `git log`, читати локальні docs.
UI або permission policy все одно можуть попросити підтвердження конкретного tool call.

**Потребує окремого підтвердження:** кожен запис або редагування файла в manual mode,
MCP-виклики, shell-команди поза allow-list, встановлення залежностей, commit і push,
зовнішні дії.

**Заборонено:** secrets і `.env`-файли, destructive-команди, force push
і перезапис змін користувача.

**Плани не є дозволом.** План, погоджений у чаті, не дає автоматичного права записувати файли.
Погодження плану та підтвердження конкретного запису — два окремі кроки:
кожен запис або редагування файла підтверджується окремо, навіть коли план уже прийнято.

**Статус:** прийнято з уточненням про окреме підтвердження запису файлів.
